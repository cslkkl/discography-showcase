## 三、环境事实（影响所有读数，先读这节）

1. **视口以页面内 `innerWidth` 自证，不乘任何系数。** 本机用独立进程
   `chromium.launch()` + `newContext({viewport})` 时，`viewport` 就是 CSS 像素：
   请求 1440×900 → `innerWidth=1440 / innerHeight=900 / dpr=1`；1366×768、390×844 同理。
   脚本把这条写成断言（META 组，四模式 PASS）。
   共用 MCP 浏览器曾出现「请求 1440 得到 CSS 1920」，那是**那个浏览器窗口自身的缩放**，
   不是机器事实，不要升格、也不要把「乘 0.75」写进测试辅助函数。
2. **当前产物播的是远端 30 秒试听，不是本地 sidecar。** `js/data.js` 里
   `assets/audio/` 引用 **0** 条、`itunes.apple.com` 引用 **2642** 条。
   所以「972/1104 首可整首播放」「885 首有歌词」这两条验证快照在**这份产物上验不到**；
   本文所有播放断言的实际媒体源是 `https://audio-ssl.itunes.apple.com/...m4a`（`duration≈30`）。
   谁若拿当前产物报告「整首播放通过」，就是没看数据源。
3. 播放因此是**网络相关**的：断言必须等 `currentTime > 0` 而不是固定 sleep
   （实测点击后 900ms 仍可能是 0）。
4. 四模式 `pageerror` 全为 0，无 `console.error`。

## 十一、对抗性复查：最可能被漏掉或造假的三点

1. **测试辅助函数在真实点击失败时静默回退成 `element.click()`，会直接把 3D 命中类回归
   变成假绿。** 本次升级最严重的那个缺陷（祖先 `perspective` + 子层 `preserve-3d` 吃掉
   后排卡片命中）**只有真实指针点得出来**：DOM 断言、`elementsFromPoint`、`element.click()`
   全部通过。我第一版脚本的 `tryClick()` 就是这种回退结构，若没另写严格路径，
   这个回归会完整地躲过验收。任何声称「点击功能正常」的结论，都必须说明它是用
   `page.mouse.click()` 验的。
2. **`document.elementsFromPoint` 不是命中真相，差额可以极大。** 窄屏远端封面上
   几何命中 4980/5016（99.3%）、真实命中 0/5016（0%）。用 DOM 命中测试去证「元素可点击」
   会给出一片假绿。判「某点能否真的点到某元素」必须用浏览器自己的 `el.matches(':hover')`
   挑点，再用 `page.mouse.click()` 落锤。
3. **播放类验收的媒体源被忽略。** 当前 `js/data.js` 的 `assets/audio/` 引用为 **0**，
   2642 条指向 iTunes 远端；而验证快照写的是「972 首可整首播放、885 首有歌词」。
   照抄快照去报「整首播放/歌词舞台通过」，验的其实是 30 秒试听。
   播放断言还必须在网络条件下等 `currentTime > 0`，固定 sleep 会得到 t=0 的假失败
   （反过来，只断言 `paused=false` 又会在数据尚未缓冲时给假绿——`play()` 立刻就把
   `paused` 置 false）。
4. （附）**命名漂移**：验收任务书写的 `.pl-toggle` 在 DOM 里不存在（实际是 `#plToggle`），
   `#heroEn` 也不存在（实际 `#haEn`）。照抄写出的断言会永远是 0/空值——
   这类「选择器恒假」的断言比缺断言更危险，因为它看起来在测。

## 十二、测量方法论（本次踩到并已规避的坑）

1. **量样式前 `bringToFront()`**：背景分页的 CSS transition 会冻结在起始值。
2. **遍历 CSSOM 用 `rule.selectorText !== undefined` 判普通规则**，
   不能用 `if (rule.cssRules)`：Chrome 给普通 `CSSStyleRule` 也挂了空 `cssRules`，
   会把全部规则当嵌套规则跳过，得到「选择器不存在」的假象。
3. **`elementsFromPoint` 不是命中真相**（见第十一节）。
4. **测试辅助函数不得静默回退**（见第十一节）。
5. **视口以 `innerWidth` 自证，不要乘系数**（见第三节）。
6. **主视觉「过场尾部」远长于「类编排」**：`is-shifting 340 + is-arriving 620 = 960ms`
   时类已收尾，但 1600ms 时中央卡的 transform 仍是 `matrix3d(0.999705, …)`，
   右二那张还停在上一格。更阴的是**卡片会「路过」其他合法宽度**
   （319 → 246 途中是 302），所以「连续若干次采样不变」会在假格位上误判落定。
   正解：等到宽度多重集与 `--fx` 集合都等于目标值，且连续 3 次采样不动。
   本项实测落定：desktop 1327ms、laptop 1336ms、mobile 1217ms、reduced 304ms
   （该口径含约 300ms 的连续采样确认窗口，故桌机底层约 1040ms，
   与实现方声称的 ~1042ms 一致）。
7. **`locator.hover()` 会先 `scrollIntoViewIfNeeded`**：在未落定的版面上量悬停，
   它会把 `.fan` 的祖先容器横向卷动 58px，五张卡一起位移——表现为
   「全部让开、宽度不变」，像极了真实避让。必须先在落定版面用元素矩形算点，
   并断言容器 `left` 未变。
8. **判「就地换歌手」不能用 `framenavigated`**（`pushState` 也触发）；
   要用页面内标记 + `page.on('load')` 计数。
9. **`closeSheet()` 有 620ms 拆除延迟**：先移除 `.is-open`，620ms 后才置
   `hidden = true`。按 Esc 后只等 600ms 会读到「还开着」的假失败。
10. **歌手页目录区三个分页的上次选择存在浏览器 context 里**：量单一视图前先点对应分页，
    否则量到 `display: none` 的容器。
11. **量首屏折线前必须回到顶部**：`getBoundingClientRect` 是视口相对坐标。
12. **`hero 与下一段 gap = 0`**：「露出下一段」不是 `nextTop − heroBottom`（恒 0），
    而是 `vh − nextTop`。写错会把一个正常版面报成 0px 缺陷。
