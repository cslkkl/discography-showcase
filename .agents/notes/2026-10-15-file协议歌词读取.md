# 決策：`file://` 下的歌詞讀取（2026-10-15）

状态：生效

## 問題

歌詞文本不進 `js/data.js`（第三方版權文本），而是與音檔同目錄的 sidecar `.lrc`
（`assets/audio/<專輯id>/<序號> <歌名>.lrc`），由 `js/lyrics.js` 在播放或開檔案時取回。
取檔一直用 `XMLHttpRequest`，而 `file://` 下瀏覽器禁止 XHR 與 fetch 讀本機檔案，
於是**每一首**都報「歌詞載入失敗」，實測原話：

```
Access to XMLHttpRequest at 'file:///…/assets/audio/jay2000/09 龍捲風.lrc' from origin 'null' has been blocked by CORS policy
```

同一個檔走 `http://127.0.0.1:8099` 則完全正常（周杰倫〈龍捲風〉49 行）。
實測三種取檔方式在 `file://` 下的可用性（動態插入腳本、探針文件、測完即刪）：

- `XMLHttpRequest` → `onerror`
- `fetch` → 拋 `Failed to fetch`
- 動態 `<script src>` → **成功**（能讀到同目錄子路徑的 js 文件）

這與倉庫對外的承諾直接衝突：`file://` 下入口、歌手頁與播放都能用，只有歌詞全滅。

## 決策

- **本機態（`--local`）額外生成 `js/lyrics/<專輯id>.js`**：每個檔開頭是
  `window.LYRICS = window.LYRICS || {};`，逐首一行
  `window.LYRICS["<專輯id>-<序號>"] = "<歌詞全文>";`（用 `JSON.stringify` 轉義）。
  實測規模：81 個專輯檔、合計 2,042 KB，覆蓋 901 首有歌詞的曲目
- **`js/lyrics.js` 新增 `loadText()`**，取檔順序三級：記憶體裡已有內聯文本 →
  動態插入 `<script src="js/lyrics/<專輯id>.js?v=<與 data.js 同一個版本戳>">` →
  兩者都取不到才退回原來的 XHR
- **專輯 id 從 `track.lyrics` 的路徑正則取出**（`assets/audio/<專輯id>/…`），
  所以**沒有改 `app.js` 的呼叫簽名**
- **payload 載入成功但沒有這一首的鍵時，視為「這首沒有歌詞」**，不再退回 XHR
  （伴奏槽就是這種情形，退回只是白跑一次必然失敗的請求）
- **公開建置把整個 `js/lyrics/` 目錄刪掉**，公開產物零歌詞
- **忽略清單三處**：`.gitignore` 的 `js/lyrics/`（第三方版權歌詞文本，與
  `assets/audio`、`local-lyrics.json` 同進出）、`.prettierignore`、`eslint.config.js`
  的 `ignores`（生成物不參與 lint 與 format，與 `js/data.js` 同口徑）
- **順帶把誤導性的失敗文案改準**：拿到文本卻解析不出行時（全庫 33 首純文本無時間軸，
  全在林志炫），提示由「歌詞載入失敗」改為「這首歌詞檔沒有時間軸」

## 替代方案（強制）

- **(a) 把歌詞文本內聯進 `js/data.js`**：否決。`index.html` 也會載入 `js/data.js`，
  入口頁根本不需要歌詞，本機態卻要多解析約 1.9 MB；而且 `js/data.js` 是要公開的產物，
  歌詞會差點被帶進公開建置，得再加一套「本機態才有、公開態逐位元組剔除」的分支
- **(b) 只改文案說「請用 http:// 打開」**：否決。倉庫承諾過 `file://` 可用，
  這樣等於讓雙擊打開 html 的用戶永遠看不到歌詞，是把瀏覽器的限制轉嫁給用戶
- **(c) 用 `fetch`／XHR 加 `--allow-file-access-from-files` 啟動參數**：否決。
  那是要用戶改瀏覽器啟動方式，站點不該有這種前提，也不可能寫進任何使用說明
- **(d) 把歌詞改存成 JSON 讓腳本 XHR**：否決。`file://` 下 JSON 一樣是
  XHR／fetch 取得，同樣被 CORS 擋掉，換容器不換通道等於沒改
- **(e) 逐首一個 payload 文件**：否決。901 個文件太碎，目錄與請求數都不划算；
  按 81 張專輯分檔剛好一次按需載入一整張，與播放列「整張連播」的用法也對得上

## 驗收證據

- `file:///…/artist.html?a=jay-chou` 點〈龍捲風〉的「阅读歌词」→ 舞台打開、
  `Jay · 龍捲風 · 49 行`、`console error 0`（改前是 6 條 CORS 報錯）
- `http://127.0.0.1:8099/artist.html?a=terry-lin` → 〈時間的味道〉27 行正常；
  新接上的〈離人〉49 行正常；無時間軸的〈心上〉現在提示「這首歌詞檔沒有時間軸」
- `npm run build`（公開態）→ `js/lyrics/` 被刪除
- `npx eslint js/lyrics.js _data/build.mjs` 0 問題

## 影響

- 公開產物仍是 0 歌詞：公開建置刪掉整個 `js/lyrics/`，版本庫也不追蹤它
- 本機態多出 2.0 MB 的 `js/lyrics/`（81 檔、實測 2,042 KB），
  但只在該張專輯的歌詞真的要用時才按需載入一個檔
- 歌詞取檔多了一條 `<script>` 通道，XHR 仍在：`http://` 預覽與舊產物照舊走它
- `window.LYRICS` 是新的全域，只在 payload 載入成功後存在，不是 `JC` 的一部分
- `file://` 的可用性承諾由「入口、歌手、播放」擴到「歌詞」，驗證快照同步改寫
