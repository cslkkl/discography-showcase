# 决策：主题分三层，歌手与专辑各有人格（2026-10-12）

状态：生效

## 问题

多歌手模板落地后，维护者要求每位歌手有个人风格元素（歌风、性格），
且同一歌手的每张专辑也要有自己的元素——不能千篇一律。
原全局规则「全站唯一强调色」与之冲突。

## 决策

主题分三层，逐层覆盖，个性来自数据而非复制样式：

- 站点层：深墨底、颗粒、品牌字，全站共享，不随歌手变
- 歌手层：`meta.mjs` 的 `theme`（accent / accentOn / motif / heroTitle），
  由 `applyArtistChrome()` 写入 CSS 变量与 `data-motif`，母题集中在 `css/motifs.css`
- 专辑层：构建期从每张封面的 `vivid` 与 `lum` 派生强调色与文字色，
  明度分界 0.5，暗于 0.18 提亮、亮于 0.82 压暗；运行时注入抽屉面板

规则同步改写：全站唯一强调色 → 每位歌手单一强调色（同一歌手页内仍只有一个）；
入口页中性底，以各歌手的强调色作点缀。

## 替代方案（强制）

- 每位歌手复制一份完整样式表：改一次公共样式要同步 N 份，必然漂移
- 只换强调色不做母题：个性停留在颜色，表达不了歌风与性格
- 母题用大量图片素材：体积与授权成本高，且 CSS 可表达的晕染与描边已足够克制
- 专辑层配色人工指定：十六张逐个配色不可维护，封面派生既自动又忠于唱片本身

## 影响

- 收益：个性由数据驱动（编辑层 + 封面），新增歌手填 `theme` 即得人格；
  抽屉打开即换色，同一歌手的每张专辑视觉可区分
- 代价：`theme` 进入 `DISCOGRAPHY` 契约与专辑契约；`color-mix` 与
  `color-mix` 依赖的现代浏览器成为母题的前提（旧浏览器降级为无晕染，版式不受影响）
- 周杰倫保持朱砂不变；`ink` 母题为主视觉加淡墨晕、为两枚印章加印痕描边
