# 决策：升级为多歌手模板（2026-10-12）

状态：生效

## 问题

维护者日后要做薛之谦等其他歌手的陈列，问仓库名与结构是否要换。
原架构把「歌手」焊死在三层：数据文件名、全局变量 `window.JC`、页面文案。

## 决策

- 仓库定名 `discography-showcase`（公开托管），与歌手解耦
- 数据层按歌手分文件夹：`_data/artists/<id>/{albums-raw.json, colors.json, meta.mjs}`
- `build.mjs` 改为遍历 `artists/*`，输出 `window.DISCOGRAPHY = { toSimplified, order, artists }`
- 页面拆成两层：`index.html` 为歌手索引（入口），`artist.html?a=<id>` 为歌手陈列页
- 歌手頁內部把當前歌手的展示集賦值給內部變量 `JC`，渲染層全部沿用 `JC.*`，
  因此十四個展示面的渲染函式零改動
- 頁面上寫出歌手名字的槽位（標題、印章、品牌副題、眉題、首行、MediaSession）
  全部由 `applyArtistChrome()` 從編輯層填充，HTML 只留周杰倫作為後備
- 頂欄加歌手切換器（選單列出全部歌手，尾附「所有歌手」回入口）

## 替代方案（强制）

- 一歌手一倉庫：封面、字體（10.9 MB）、腳本各複製一份，且樣式修一次要改 N 個倉
- 單頁內切換（不拆入口頁）：`index.html` 同時承擔「選歌手」與「陳列」兩種形態，
  路由與狀態管理變複雜，且「點進去選歌手」的入口感就沒有了
- 動態 import 歌手資料檔（按需載入）：`file://` 下 script 標籤可以同步載入，
  但按參數注入 script 標籤需要 `document.write` 一類手段；單一 data.js 在本地
  場景下 137 KB/歌手，完全可接受，簡單得多

## 影响

- 收益：新增歌手 = 新增資料夾 + `npm run build`，渲染層與構建器零改動；
  每位歌手的事實、文案、清洗規則集中在一個資料夾內
- 代價：`js/data.js` 的形狀變了（`JC` → `DISCOGRAPHY.artists[id]`），這是契約破壞；
  `index.html` 的語義從「歌手站」變成「入口」，快速開始多一步
- 已知取捨：入口頁的繁簡轉換是 landing.js 內的精簡實作，與 app.js 的 localize
  是兩份程式碼；理由是不為一個靜態頁引入整個渲染器，已記入 js/README
- 抓取腳本（`fetch-previews.ps1` / `extract-colors.ps1`）改為接受 `-Artist` 參數
